Which planner layout should we design toward?

All three use the real /new dark theme, tokens and type scale — and all three deliberately use the actual FFCS day/THEORY/LAB slot-grid shape instead of a generic hourly calendar. The difference is where the grid sits, how big it gets to be, and where course-adding controls go.

Every mockup shows the same underlying state on purpose: 2 courses added, one of them clashing with an existing pick in the same slot. Watch how each layout handles that clash and signals "this isn't generated yet."

Evaluate each option on

  • How dominant is the timetable, really — first thing you see, or competing with chrome?
  • How much space do Search / Paste / Import / Manual controls take, and where do they live?
  • How obvious is "this is a draft, not a generated schedule" — without adding a decorative box?
  • How is a slot clash represented, and does it stay legible at this density?
  • How cleanly would this hand off to the real FPSlotMatrixTimetable once you hit "Find my weeks"?

Conventions used consistently across all three

◐ Draft preview · not generated — reuses the same amber "warn" tone the app already uses for Stale/Unverified states, so "provisional" reads as a status, not a new visual language.
2 courses — a clashing cell: diagonal split of both course colors + a warning glyph, distinct from a normal single-course cell. This is the same slot the real generator would reject as infeasible.
